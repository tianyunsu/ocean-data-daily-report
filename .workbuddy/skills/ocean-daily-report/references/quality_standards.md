# 海洋AI研究日报 — 质量标准

## 时效性规则

### 分档口径（2026-09-15 用户拍板）

| 档位 | 处理 |
|------|------|
| **≤7 天** | **优先收录**；同方向内候选超额时按此档优先排序 |
| **8-14 天** | 合格，正常收录 |
| **15-60 天** | 仅"重要性豁免"可收录（见下），否则剔除 |
| **>60 天** | **一律删除**，不得收录 |

### 常规条目
- **≤14 天**（自原始发布日期算起）为合格
- 失效条目必须替换，不得滞留

### 近 7 天优先权重（排序规则，非硬门槛）
同一方向内候选条目多于 5 条时，**按发布日期由近及远排序，优先取近 7 天内的**。
- 目的：在维持 ≤14 天窗口的前提下，让简报的"新鲜度"尽可能高。
- 注意：这**只是排序权重**，不构成"超过 7 天即不合格"的门槛——8-14 天的合格条目仍可收录。

### 重要性豁免
满足以下**全部条件**可放宽至 ≤60天：
1. 事件重要性高（顶级期刊发表、重大政策、里程碑数据发布等）
2. 不与历史日报（**近 12 期**）内容重复
3. 在摘要中标注原始日期，便于读者判断时效

### 单期规模
- 每方向目标 **3-5 条**，全日报 **27-45 条**
- 某方向确实无新进展时**可为 0**：不填充陈旧内容，标注"暂无明显进展"或缩减条目数
  （"宁缺不凑数"优先于"凑满 3 条"）

## 去重规则

对比**最近 12 期历史日报**，确保今日内容无重复（**不是只看 5 份**）：

- 检查路径：`$GH_REPO/posts/` 下最近 **12 个** `.html` 文件，提取全部 `href` 做集合差
- **多路 grep**：除 URL 外，同时用 **标题关键词 + 期刊卷期号 + 作者 + DOI 尾号** 检索历史期
  （集合比对挡不住"同一期不同文章此前已各自收录"，见 SKILL.md 常见陷阱 11）
- 权威基准：`$GH_REPO/.workbuddy/memory/MEMORY.md` 的"去重基准（滚动更新）"小节
- 重复判定：同一事件/论文/产品不可出现在两份日报中
- 续报例外：若同一事件有重大更新（如论文 preprint→正式发表、数据集版本升级），可再次报道，但需标注"更新"
- **用户点名条目与去重冲突**时，按 SKILL.md 常见陷阱 9 的流程处理——不默默照做，也不默默拒绝

## 方向归类严格规则（2026-05-18 质检教训，每次生成日报前必须逐条对照）

**只有内容的核心主题匹配才能归入对应方向：**

| 方向 | 可收录内容 | 禁止归入 |
|------|-----------|---------|
| 一、海洋AI | AI/ML/DL 模型用于海洋预报、观测、生态模拟；AI 海洋学理论 | 一般数值模型、非 AI 方法 |
| 二、数字孪生 | 海洋数字孪生架构/框架/应用案例/DT 会议 | 一般 AI 模型、纯数值模型 |
| 三、可视化 | 可视化方法/工具/平台/GIS/Dashboard/地图制作技术 | 纯生态学/物理海洋学论文（即使论文中有图表） |
| 四、数据质量 | QA/QC 方法、质量控制流程、数据异常检测、精度评估 | 海底测绘进展统计、数据集发布公告 |
| 五、数据处理 | 数据再处理方法、融合算法、插值/重采样/降尺度技术 | 软件工具版本发布（→归九）、培训活动（→归六） |
| 六、数据管理 | 数据政策、FAIR 原则、共享平台（**含地质样品共享**）、元数据标准、培训活动、开放数据政策 | 软件工具发布 |
| 七、开放航次 | 科考航次、调查船（**含船时共享**）、海上作业、潜水器、无人船、海洋装备 | 陆基研究 |
| 八、海洋数据中心 | 海洋数据仓库/档案馆（NCEI、PANGAEA、CMEMS）、数据集发布 | IT 计算基础设施（海底服务器机房不归此）、纯气候动力学论文（若无合适方向则不收录）、纯海平面/生态学论文 |
| 九、工具代码 | 软件工具/代码库/开发框架的新版本发布、技术迁移指南 | 数据处理方法论文 |

**关键规则（违反将导致严重归类错误）：**

- **宁可某方向为空（0 条），也不凑数填入不相关内容**——"宁缺不凑数"优先于"凑满 3 条"
- **"海底数据中心"新闻**：如果报道的是 IT 基础设施（海底服务器机房用于冷却），这不是海洋数据仓库，**不得归入方向八**，应直接不收录
- **Nature Communications / Science 等综合期刊论文**：必须按论文实际内容归类，**不能因为期刊名含"Nature"就归入某方向**
- **同软件不同 URL**（如 PyPI 页面和 GitHub release 页面）：**只能在日报中出现一次**，归方向九
- **生态学论文**（海带森林、浮游植物、珊瑚礁等）：除非论文核心贡献是可视化方法，否则**不归方向三**
- **气候变化/物理海洋学论文**（AMOC、海平面、ITCZ 等）：归入方向八**仅当**论文是关于数据中心发布的状况报告；纯研究论文若无合适方向则不收录

### 归类自检（生成 SECTIONS 后、写入文件前必须执行）

对每条内容回答：**这条内容的核心主题是否与所在方向的定义匹配？**
不匹配的，要么移到正确方向，要么删除。自检结果（改归/删除了几条及原因）**记入当日工作日志**。

## 日期核实规则

### 搜索引擎日期不可信
搜索引擎在结果旁显示的日期可能是**网页索引日期、最后修改日期、或缓存日期**，并非文档的原始发布日期。以下来源尤其需要警惕：
- UNESCO/FAO/IOC 等国际机构文档库（如 `unesdoc.unesco.org`）
- 学术数据库的详情页
- 政府机构网站

### 顶会论文日期规则
会议论文存在多个日期节点，容易混淆。请按以下优先级确定条目 `date`：

**默认规则（预印本视角）**：
- **以首次公开可访问的日期为准**（通常为 arXiv 预印本 v1 发布日或 OpenReview 公开日）
- **不以会议召开日为准**：CVPR 2026 会议可能 6 月召开，但论文可能早在 2025 年 11 月就上了 arXiv
- 若论文仅有 OpenReview 链接无 arXiv 版本，以 OpenReview 公开日为准
- workshop 论文通常与主会论文同期或稍晚公开

**IEEE 期刊日期规则**：
- 以 **IEEE Xplore 上的 Early Access 上线日**为 `date` 字段（即首次公开发布日），**不以正式卷期（Issue）出版日为准**——Early Access 可能早于正式卷期数月
- GRSM/TGRS 等期刊的重磅综述若 Early Access 上线 ≤60 天且与历史不重复，按"顶级来源"豁免收录

**例外规则（以会议为新闻时点）**：
当某篇论文的"新闻价值"在于其**被顶会录用/接收、或会议正式召开**时（而非作为预印本首次公开），允许以**会议接收日期或会议举办日期**作为条目 `date`，并在标题中标注会议来源，如 `"方法名"（CVPR 2026）`。须同时满足：
1. 论文确为该会议**正式录用/接收**论文（非纯 workshop 滚动投稿、非仅为投稿）；
2. 新闻时点（会议录用公告/会议召开）落在时效性窗口内（或按重要性豁免）；
3. 摘要中**必须同时注明预印本原始公开日**（如"arXiv:xxxx，2025-11"），以保留时效性透明度。
该例外仅用于"以会议为新闻时点"的条目；**纯预印本（无会议录用）一律使用 arXiv v1 或 OpenReview 公开日**，不得套用会议日期。

### 反爬站点（MDPI / ScienceDirect / Wiley / IEEE 等）核实规则

这类站点对 urllib/Requests 常返回 **403（Cloudflare 反爬）**，部分还会返回"200 但内容是挑战页"（如 PyPI 的 `Client Challenge`）。**403 ≠ 死链，不得据此剔除条目。**

**首选方案：用官方元数据 API，根本不抓网页**（推荐，最快最准）
仓库根目录提供 `verify_paper.py`：

```bash
python verify_paper.py 10.3390/su18178986              # 单个 DOI 或含 DOI 的 URL
python verify_paper.py <doi1> <doi2> --today 2026-09-07  # 批量 + 指定基准日
python verify_paper.py <doi> --json                    # JSON 输出，供脚本消费
```

数据源为 **Crossref**（出版方注册数据，权威）+ **OpenAlex**（含摘要、OA、被引）交叉校验，
免费、公开、合法、无需 API key、不受反爬影响。一次拿到：标题 / 期刊 / 作者 / 发表日期 / 摘要 / OA 状态 / 时效判定。

判定要点：
- **两源日期一致** → 直接采信
- **两源日期不一致** → 以出版方/首次公开日为准，并用 WebFetch 打开原文复核（如 Elsevier 常见 Crossref 记正式发表日、OpenAlex 记 available-online 日）
- **Crossref 只精确到月/年** → 工具按当月 1 号估算并提示，须 WebFetch 补准确日
- **API 无摘要** → 用 WebFetch 补（多为 OA closed 的订阅制期刊）

**备选方案：WebFetch 二次确认**
API 取不到（如尚无 DOI 的新闻稿）时，用 WebFetch 打开原文，确认标题、作者、期刊、发布日期与条目一致即可判定链接有效。

**不推荐**：代理池、伪造 UA 批量抓取、绕过付费墙等手段——违反站点 ToS、不稳定，且日报只需要元数据而非全文，无必要。

### 交叉验证要求
编写条目前，必须对日期做以下核实：
1. **内容交叉验证**：若摘要提及某会议/事件（如"IODE第26次会议推动"），搜索确认该事件的实际召开年份，与条目日期做比对——如果事件发生在数年前，条目日期大概率不是发布日期
2. **多源比对**：至少用一个独立来源（如 AGRIS、OceanExpert、出版商页面）确认文档发布年份
3. **合理性质疑**：若搜索引擎日期显示为"今年本月"但文档标题/内容涉及多年前的战略计划、政策框架等，必须深入核实

### 时效性审计的局限
阶段四的时效性审计仅检查 `date` 字段是否在窗口内。如果 `date` 本身是错误的搜索引擎日期，审计会假性通过。因此**日期核实必须在阶段一搜集时完成**，不能依赖阶段四兜底。

## 链接验证与摘要一致性

### 链接有效性（必须验证）
- 所有 `.html` 中的 `<a href>` 链接
- 验证标准：返回 HTTP 200，非 404/403/500/重定向到错误页
- 使用 `WebFetch` 逐个验证，每链接超时 10 秒；反爬站点改用 `verify_paper.py`
- **严禁凭 URL 模式推断或拼装链接**（见 SKILL.md 常见陷阱 10）
- 条目 `url` **不得指向机构/平台首页**，必须给到承载该内容的页面（陷阱 13）

### 验证后处理
- 失效链接：搜索替代来源或可信镜像
- 检索结果只有转载稿时，改用可访问的权威转载源并如实标注转载关系
- 极特殊情况下（如 PDF 链接无法 WebFetch 验证），可标注 `[需手动验证]` 但仍然保留

### 摘要与原文一致性（必须核对，易漏）
逐条核对简报摘要与原文内容是否相符：

- 摘要须**准确反映原文核心观点**，不得出现与原文不符的表述
- **关键事实必须能在原文中找到出处**：数字（精度、分辨率、样本量、天数、金额、温度、坐标）、
  方法名、机构名、人名、时间点
- **不得张冠李戴**：批量导入时最容易把相邻条目的事实混入（把 A 条的数据写进 B 条）
- 无法核实摘要表述的条目，要么改写为原文明确支持的说法，要么剔除

## 内容质量标准

- **规模**：每方向 **3-5 条**，全日报 **27-45 条**；某方向确无新内容可为 0，不凑数
- 每条目包含：标题、标签（[论文]/[要闻]/[动态]/[工具]/[数据]/[报告]/[政策]/[航次]/[开源]/[关注]）
- 摘要：2-4 句独立完整，涵盖"谁做了什么、为什么重要"
- 来源：机构+平台名称，不用模糊表述
- 日期：YYYY-MM-DD 格式
- **代码约定**：写入 `SECTIONS` 的字符串值**统一用单引号**，避免双引号嵌套导致 SyntaxError
