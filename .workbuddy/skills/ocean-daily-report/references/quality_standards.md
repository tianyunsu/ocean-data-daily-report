# 海洋AI研究日报 — 质量标准

## 时效性规则

### 常规条目
- **≤14天**（自原始发布日期算起）为合格
- 失效条目必须替换，不得滞留

### 重要性豁免
满足以下**全部条件**可放宽至 ≤60天：
1. 事件重要性高（顶级期刊发表、重大政策、里程碑数据发布等）
2. 不与历史日报（最近5份）内容重复
3. 在摘要中标注原始日期，便于读者判断时效

### 无新内容处理
某方向确实在窗口期内无新进展时，**不填充陈旧内容**。改为标注"本周暂无明显进展"或缩减该方向条目数。

---

## 去重规则

对比**最近5份历史日报**（如果存在），确保今日内容无重复：
- 检查路径: `posts/` 目录下最近5个 `.html` 文件
- 重复判定：同一事件/论文/产品不可出现在两份日报中
- 续报例外：若同一事件有重大更新（如论文 preprint→正式发表），可再次报道，但需标注"更新"

## 日期核实规则

### 搜索引擎日期不可信
搜索引擎在结果旁显示的日期可能是**网页索引日期、最后修改日期、或缓存日期**，并非文档的原始发布日期。以下来源尤其需要警惕：
- UNESCO/FAO/IOC 等国际机构文档库（如 `unesdoc.unesco.org`）
- 学术数据库的详情页
- 政府机构网站

### 顶会论文日期规则
会议论文存在多个日期节点，容易混淆。请按以下优先级确定条目 `date`：

**默认规则（预印本视角）**：
- **以首次公开可访问的日期为准**（通常为 arXiv 预印本 v1 发布日或 OpenReview 公开日）
- **不以会议召开日为准**：CVPR 2026 会议可能 6 月召开，但论文可能早在 2025 年 11 月就上了 arXiv
- 若论文仅有 OpenReview 链接无 arXiv 版本，以 OpenReview 公开日为准
- workshop 论文通常与主会论文同期或稍晚公开

**IEEE 期刊日期规则**：
- 以 **IEEE Xplore 上的 Early Access 上线日**为 `date` 字段（即首次公开发布日），**不以正式卷期（Issue）出版日为准**——Early Access 可能早于正式卷期数月
- GRSM/TGRS 等期刊的重磅综述若 Early Access 上线 ≤60 天且与历史不重复，按"顶级来源"豁免收录

**例外规则（以会议为新闻时点）**：
当某篇论文的"新闻价值"在于其**被顶会录用/接收、或会议正式召开**时（而非作为预印本首次公开），允许以**会议接收日期或会议举办日期**作为条目 `date`，并在标题中标注会议来源，如 `"方法名"（CVPR 2026）`。须同时满足：
1. 论文确为该会议**正式录用/接收**论文（非纯 workshop 滚动投稿、非仅为投稿）；
2. 新闻时点（会议录用公告/会议召开）落在时效性窗口内（或按重要性豁免）；
3. 摘要中**必须同时注明预印本原始公开日**（如"arXiv:xxxx，2025-11"），以保留时效性透明度。
该例外仅用于"以会议为新闻时点"的条目；**纯预印本（无会议录用）一律使用 arXiv v1 或 OpenReview 公开日**，不得套用会议日期。

### 反爬站点（MDPI / ScienceDirect / Wiley / IEEE 等）核实规则

这类站点对 urllib/Requests 常返回 **403（Cloudflare 反爬）**，部分还会返回"200 但内容是挑战页"（如 PyPI 的 `Client Challenge`）。**403 ≠ 死链，不得据此剔除条目。**

**首选方案：用官方元数据 API，根本不抓网页**（推荐，最快最准）
仓库根目录提供 `verify_paper.py`：

```bash
python verify_paper.py 10.3390/su18178986              # 单个 DOI 或含 DOI 的 URL
python verify_paper.py <doi1> <doi2> --today 2026-09-07  # 批量 + 指定基准日
python verify_paper.py <doi> --json                    # JSON 输出，供脚本消费
```

数据源为 **Crossref**（出版方注册数据，权威）+ **OpenAlex**（含摘要、OA、被引）交叉校验，
免费、公开、合法、无需 API key、不受反爬影响。一次拿到：标题 / 期刊 / 作者 / 发表日期 / 摘要 / OA 状态 / 时效判定。

判定要点：
- **两源日期一致** → 直接采信
- **两源日期不一致** → 以出版方/首次公开日为准，并用 WebFetch 打开原文复核（如 Elsevier 常见 Crossref 记正式发表日、OpenAlex 记 available-online 日）
- **Crossref 只精确到月/年** → 工具按当月 1 号估算并提示，须 WebFetch 补准确日
- **API 无摘要** → 用 WebFetch 补（多为 OA closed 的订阅制期刊）

**备选方案：WebFetch 二次确认**
API 取不到（如尚无 DOI 的新闻稿）时，用 WebFetch 打开原文，确认标题、作者、期刊、发布日期与条目一致即可判定链接有效。

**不推荐**：代理池、伪造 UA 批量抓取、绕过付费墙等手段——违反站点 ToS、不稳定，且日报只需要元数据而非全文，无必要。

### 交叉验证要求
编写条目前，必须对日期做以下核实：
1. **内容交叉验证**：若摘要提及某会议/事件（如"IODE第26次会议推动"），搜索确认该事件的实际召开年份，与条目日期做比对——如果事件发生在数年前，条目日期大概率不是发布日期
2. **多源比对**：至少用一个独立来源（如 AGRIS、OceanExpert、出版商页面）确认文档发布年份
3. **合理性质疑**：若搜索引擎日期显示为"今年本月"但文档标题/内容涉及多年前的战略计划、政策框架等，必须深入核实

### 时效性审计的局限
阶段四的时效性审计仅检查 `date` 字段是否在窗口内。如果 `date` 本身是错误的搜索引擎日期，审计会假性通过。因此**日期核实必须在阶段一搜集时完成**，不能依赖阶段四兜底。

## 链接验证

### 必须验证
- 所有 `.html` 中的 `<a href>` 链接
- 验证标准：返回 HTTP 200，非 404/403/500/重定向到错误页
- 使用 `WebFetch` 逐个验证，每链接超时 10 秒

### 验证后处理
- 失效链接：搜索替代来源或可信镜像
- 极特殊情况下（如 PDF 链接无法 WebFetch 验证），可标注 `[需手动验证]` 但仍然保留

## 内容质量标准

- 每条目包含：标题、标签（[论文]/[要闻]/[动态]/[工具]/[数据]/[报告]/[政策]/[航次]/[开源]/[关注]）
- 摘要：2-4句独立完整，涵盖"谁做了什么、为什么重要"
- 来源：机构+平台名称，不用模糊表述
- 日期：YYYY-MM-DD 格式
